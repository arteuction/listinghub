# Admin Experience Studio - locked product scope

Status: **3.6.0 scope locked; 3.6.0A–E implemented. 3.6.1 (Form Builder) next.**

This document records which product ideas are carried into ListingHub from the
reviewed directory-platform references. They are functional references only.
ListingHub remains an original Laravel 13 implementation and does not copy
legacy source code, database design or unsafe runtime customization patterns.

Reference review: *Technical documentation Atlas Laravel* (199 pages), with
the relevant flows on categories (pp. 13-16), custom content fields (pp. 84-86),
directory-type sorting (pp. 97-104), website/menu/FAQ settings (pp. 137-149),
form builder and scoped SEO (pp. 150-154).

## Accepted capabilities

### Structured content and pages

- Tiptap WYSIWYG for About, Contact, Terms, Privacy, Refund Policy and other
  administrator-created pages.
- Reusable, allow-listed blocks: rich text, hero, CTA, category grid, featured
  listings, FAQ, image/text, announcement, carousel, gallery, safe video,
  company-logo strip and testimonials.
- Category landing pages use the same blocks through the polymorphic owner.
- Every page and block has draft/publish workflow, preview and snapshot history.

### Direct UX control

- Drag-and-drop ordering for page blocks, menus, taxonomy terms and form fields.
- Header/footer navigation, home-page sections, announcement bar, logo and
  verified image assets are editable without a code deployment.
- The administrator may choose from design tokens and approved component
  variants, but cannot submit CSS, JavaScript or Blade templates.
- FAQ is a structured repeatable block, not one unvalidated HTML field.

### Universal classification

The references demonstrate four separate classification needs: listing
categories, directory types, amenities/tags and blog/product categories.
ListingHub will model them through one taxonomy kernel:

- `taxonomies` define a context and whether terms are hierarchical or multiple;
- `taxonomy_terms` hold the tree, icon/image, state and ordering;
- `taxonomy_termables` assign terms polymorphically;
- the existing `listings.category_id` remains the primary-category compatibility
  field until the new reads and custom-field bindings are proven;
- amenities become a non-hierarchical taxonomy with an optional icon, not a
  second hard-coded feature system;
- a taxonomy term may own ContentBlocks, giving every category a configurable
  landing page without adding category-specific columns.

### SEO and forms

- SEO metadata is scoped to a page, taxonomy term or listing: title,
  description, robots policy, canonical path and Open Graph image/text.
- Canonical URLs are validated as internal paths or approved origins.
- JSON-LD is generated by server-side schemas; administrators never paste raw
  scripts.
- A later Form Experience Builder will provide allow-listed field types,
  required/optional rules, ordering and category/listing-type assignment.
  Submissions continue through the existing lead/authorization boundaries.

## Adapted rather than copied

| Reference behaviour | ListingHub decision |
|---|---|
| Separate fixed tabs for Beauty, Car, Hotel, Restaurant | Dynamic taxonomy terms and category-owned landing pages |
| Separate settings columns for every banner and section | Versioned ContentBlocks and placements |
| Free-form video URL/embed | Provider allow-list plus normalized video identifier |
| Gallery fields inside an HTML form | Existing content-verified MediaAsset pipeline |
| Menu sorting | Sparse ordering with one server-side reorder action |
| Custom field sorting | Preserve current declarative fields and add the same safe ordering UX |
| Blog category table | Universal taxonomy when the editorial module is implemented |

## Explicit exclusions

- no runtime addon, theme or executable-code upload;
- no raw HTML, iframe, JavaScript, CSS or pasted JSON-LD;
- no payment, SMTP or OAuth secrets stored through ordinary content settings;
- no arbitrary external canonical URL;
- no permanent delete from ordinary admin screens - archive/soft-delete first;
- no language manager or multilingual listings: ListingHub remains Bulgaria-only;
- no monolithic settings row and no one-column-per-category design;
- no client-supplied base64 images; all media uses content verification and
  server-side re-encoding.

## Delivery order

1. **3.6.0A - Content foundation:** ContentBlock, optimistic versioning, full
   snapshots and append-only rollback. Implemented.
2. **3.6.0B - Rich content:** Tiptap JSON schema, server-side sanitization,
   sanitized projection and the first accessible admin editor. Implemented:
   `TiptapValidator` (allow-list walk, depth + node limits), `TiptapHtmlRenderer`
   (JSON→HTML, XSS-escaped text), `TiptapSanitizer` (renderer + HTMLPurifier
   defence-in-depth), `TiptapDocument` validation rule, `@tiptap()` Blade directive,
   Alpine/Tiptap `richTextEditor` component (17 Tiptap extensions, accessible toolbar,
   link-scheme guard, hidden-input sync). 27 unit tests (validator: 16, renderer: 11).
3. **3.6.0C - Pages and placements:** pages, navigation, block placement,
   verified media selection and drag ordering. Implemented: `pages` + `menus`
   + `menu_items` tables; `Page` / `Menu` / `MenuItem` models; `CreatePage`,
   `UpdatePage`, `PublishPage`, `UnpublishPage` actions; `ReorderContentBlocks`
   (sparse order, owner-scope guard); `SyncMenuItems` (flat + one-level nesting,
   URL scheme guard, atomic replace); `SystemPageSeeder` (6 system pages + 3 menus,
   idempotent); 16 tests.
4. **3.6.0D - Universal taxonomy:** compatibility bridge, hierarchical and
   faceted vocabularies, term-owned landing pages. Implemented: `taxonomies` +
   `taxonomy_terms` + `taxonomy_termables` tables; `Taxonomy` / `TaxonomyTerm`
   models (polymorphic content blocks, morphToMany listings); `TaxonomyTermStatus`
   enum; `CreateTaxonomyTerm`, `MoveTaxonomyTerm` (cycle guard), `AttachTermToModel`
   (allow_multiple policy), `DetachTermFromModel` actions; `TaxonomySeeder`
   (listing-categories + amenities vocabularies, bridges Category rows, idempotent);
   `categories.taxonomy_term_id` compatibility column; 16 tests.
5. **3.6.0E - Publishing governance:** preview, schedule, permissions, revision
   browser, rollback UI, cache invalidation and scoped SEO. Implemented:
   `preview_tokens` + `seo_meta` + `scheduled_publications` tables; `PreviewToken`,
   `SeoMeta`, `ScheduledPublication` models; `IssuePreviewToken` (48-char random
   token, TTL, per-creator revoke-on-reissue), `SchedulePublication` (future-only,
   replaces pending same-action, publish/unpublish co-exist), `UpsertSeoMeta`
   (robots allowlist, relative-only canonical, no base64 OG, mb_substr title/desc,
   true upsert); 14 tests.
6. **3.6.1 - Form Experience Builder:** structured lead/booking forms. Implemented:
   `form_sections` table (title, description, sort_order, is_collapsible, per-category);
   `section_id`, `placeholder`, `help_text` columns on `custom_fields`;
   `FormSection` model with `fields()` HasMany; `CustomField.section()` BelongsTo;
   `CreateFormSection` (trims, clamps sort_order ≥ 0), `UpdateFormSection` (allowlist
   guard, empty-title guard, blank-description → null), `DeleteFormSection` (rejects
   when fields exist), `ReorderFormFields` (SparseOrder, category-scope guard, dedup
   guard), `SetFormFieldValue` (typed write via `CustomFieldValueNormalizer`,
   upsert-on-update, delete-on-empty, nulls all other columns); 20 tests.

The Commerce milestone stays at 3.7.0. Blog/editorial publishing remains
deferred until the Admin Experience Studio and its permission model are proven.
